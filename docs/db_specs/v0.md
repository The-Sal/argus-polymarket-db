# APDB On-Disk Format — v0 (legacy)

`format_version: 0`. This is the format written by every APDB build prior to
the introduction of the line-0 meta record (`__apdb_meta__`). It has no
explicit version marker in the file itself — `0` is the value APDB's loader
assigns when it loads a file that doesn't contain a recognizable meta line,
introduced retroactively so `format_version` can distinguish it from
[v1](./v1.md).

## Layout

Plain **NDJSON**: one JSON object per line (`\n`-terminated), no header, no
footer, no reserved lines. Every line is a Polymarket event record.

```
{"ticker":"...", "endDate":"...", ...}\n
{"ticker":"...", "endDate":"...", ...}\n
...
```

- **Record shape:** whatever Polymarket's Gamma API returns for an event,
  serialized as-is (`poly_api::PolymarketEvent`, `extra` catch-all for
  unrecognized fields). The only field APDB itself requires is `ticker`
  (non-empty string) — it's the index key.
- **Ordering on disk:** not significant for correctness. The loader
  (`Snapshot::from_file` in `src/database.rs`) does a full sequential scan on
  load, builds an in-memory index sorted by `ticker`, and keeps only the
  *last* occurrence of a duplicated ticker (later in the file wins).
- **Compaction:** `full_crawl_and_compact` (`src/refresh.rs`) rewrites the
  whole file on every refresh — fresh crawl results plus any ticker from the
  old file the fresh crawl didn't return (never-evict merge), pruned only if
  its `endDate` is more than 4h in the past. The rewrite is atomic: written
  to `<path>.tmp`, `fsync`'d, then renamed over `path`.
- **Torn last line:** a line with no trailing `\n` (e.g. a crash mid-append)
  is dropped and logged, not treated as an error.
- **Bad/empty-ticker records:** skipped and logged individually; one bad
  record doesn't fail the whole load.

## Freshness — filesystem mtime, no TTL

v0 has no in-file notion of "when was this built." Two different signals
stood in for it, and both were unreliable:

- **`db_info`'s `built_at_unix`** (`src/api.rs`) came from the *database
  file's mtime* (`src/database.rs`, `Snapshot::from_file`), falling back to
  `now()` only if the mtime couldn't be read. Any operation that preserves
  content but not mtime — `cp`, `rsync -a` without `-t` quirks, a restore
  from backup, a plain `touch` — could make three-day-old data report as
  freshly built, or vice versa.
- **The background refresh cadence** (`POLYMARKET_FULL_MARKET_CACHE_REFRESH_INTERVAL`,
  `src/main.rs` + `src/refresh.rs`) was a literal `sleep(interval)` loop
  measured from **process start**, not from the data's actual age. On boot,
  an existing db file was loaded and served immediately regardless of age,
  and the refresh loop then waited a full `interval` before ever checking
  again. Kill the process, restart it 10 days later with a 16h interval, and
  it would serve the 10-day-old file for up to another 16h before refreshing
  — the opposite of a TTL.

This is what [v1](./v1.md) fixes: an in-file `built_at_unix` that's the
source of truth for data age, used to implement a real TTL at boot.

## Compatibility

v1's loader still reads v0 files: a file with no recognizable line-0 meta
record loads exactly as before (`format_version` reported as `0`,
`built_at_unix` falls back to mtime). No migration step is required — the
first refresh (background cycle, or the stale-at-boot refresh v1 adds)
rewrites the file with a v1 meta line.
